# Shark Learning Content Map

Run `npm run content:snapshot` before you write a count into an issue, a plan or copy. The script computes every number from the registries below; quote its output, not memory or an older document. `npm run content:snapshot -- --json` prints the same data for a script to read.

## Who owns what

| Concept | Owner | What it holds |
|---|---|---|
| Subject and its topics | `shared/subject-catalog.ts` `SUBJECT_SCOPE_CATALOG.webdev` | `topics` (offered Learn topics), `categories` (every category that still resolves, retired ones included), `questionCount`, `codingChallengeCount` |
| Retired topics | `shared/retired-content.ts` `RETIRED_TOPICS` | `testing`, `abbreviations`, `code-snippets` and where their material went |
| Learn levels | `lib/roadmap.ts` `LEVEL_TITLES`, `ID_PREFIX`, `ROADMAP_TOPICS`, `topicLevelCount` | one title per level; the level count of a topic is the length of its title list |
| Questions per level | `lib/roadmap-build.ts` `QUESTIONS_PER_LEVEL` (8), `ROADMAP_LEVELS` (25, the upper bound) | seed shape and ids; `lib/roadmap-questions-restored.ts` adds restored ids to a level |
| Served questions | `lib/questions-store.ts` `applyEligibility` over `lib/curation.ts` `questionEligibility`; `lib/roadmap.ts` `buildLiveTopic` | the bank a learner can be served; a level below `MIN_LEVEL_QUESTIONS` (3) is unavailable |
| Plan stages | `shared/progression.ts` `WEBDEV_PLAN_STAGES` | the ordered topic stages of each base track (`BASE_TRACKS` in `shared/learning-paths.ts`) |
| Plan additions | `shared/progression.ts` `SPECIALIZATION_BRIDGE_TOPICS`, `planTopics` | topics a specialization or a joined Learn section appends to the plan |
| Prerequisites | `shared/progression.ts` `TOPIC_PREREQS`, `validateProgressionGraph` | which topics open which; acyclic, every topic traces back to `STARTER_TOPICS` |
| Sections | `shared/learn-sections.ts` `LEARN_SECTIONS`, `sectionsForTopic` | the three Learn sections (Web Developer, Software Engineer, Forward Deployed Engineer) and their topic matrix |
| Tiers | `shared/tiers.ts` `contentTier`, `FREE_LEARN_TOPICS`, `FREE_LEARN_LEVELS`, `FREE_CODING_TASK_IDS`, `FREE_CODING_SHARE`, `freeCodingCounts` | what the free tier opens; the server builds its index in `lib/access.ts` `serverContentIndex` |
| Coding tasks | `lib/coding/catalog.ts` `CODING_TASKS` (authored), `lib/coding/active.ts` `ACTIVE_CODING_TASKS` (issued) | per-track tasks; `shared/coding-catalog.ts` `CODING_SECTION_TRACKS` hides `system-design` |
| Coding index | `shared/coding-index.ts` `CODING_INDEX` | generated by `npm run build:coding-index`; the only coding list the browser reads |
| Evolving projects | `shared/evolving.ts` `EVOLVING_CHALLENGES` | stage lists; `shared/tiers.ts` `freeStageCount` opens their heads |
| Learning paths | `shared/learning-paths.ts` `LEARNING_PATH_IDS`, `pathInventory`; `lib/learning-paths/catalog.ts` `LEARNING_PATHS`, `publicManifest`, `readinessFor` | path ids and kinds, the inventory arithmetic, the merged catalogue |
| FDE path content | `lib/learning-paths/content/fde.ts`, `content/fde/`; answer material in `lib/learning-paths/solutions/` | modules, lessons, checks, code exercises, artifacts. DSA is Learn content, not a path: topics `dsa` and `dsa-advanced` (`lib/learn-lessons/dsa/`, `lib/learn-lessons/dsa-advanced/`, `lib/coding/tasks/dsa.ts`, `lib/coding/tasks/dsa-advanced.ts`) |
| Path readiness | `lib/learning-paths/catalog.ts` `pathEnabledInEnv`, `availabilityFor` | a path opens when its switch is on (`LEARNING_PATH_FDE_ENABLED=true`), its content validates and its storage (migration 026) is installed |

## Invariants

- A learning path references the registries above and never joins them: `CodingTrack` and `RoadmapTopic` gain no member for a path, and `Track` keeps its three values (`shared/learning-paths.ts` header comment; `docs/product-architecture.md` "Learning paths").
- `shared/tiers.ts` is the only place that decides what the free tier opens. The server refuses locked content with 402 in `lib/access.ts` and the client mirrors it (CLAUDE.md "Protected behavior"; `shared/tiers.ts` header). The module imports nothing from `lib/`, and `tierContracts` in `scripts/test-launch-contracts.ts` fails if it does.
- `api/` holds exactly twelve physical TypeScript handlers (CLAUDE.md "Protected behavior"). A new endpoint is a `resource=` or `op=` branch inside an existing handler, never a file (`docs/product-architecture.md` "Sources of truth"). `scripts/test-launch-contracts.ts` asserts it: "Vercel function budget must remain exactly 12".
- A count in copy or a document is derived, never typed. `SUBJECT_SCOPE_CATALOG.webdev.questionCount` and `codingChallengeCount` are recomputed and asserted by `auditGateContracts` in `scripts/test-launch-contracts.ts`.
- A level keeps its authored question membership when items are withheld; a thin level becomes unavailable, it is never repacked (`lib/roadmap.ts`, the comment above `MIN_LEVEL_QUESTIONS`).
- The browser never imports `lib/learning-paths` (`docs/product-architecture.md` "Learning paths"; the "must not import lib/learning-paths" assertion in `scripts/test-launch-contracts.ts`).
- A section groups topics for presentation and plan membership. It is not a base track or a subject, and progress stays keyed by topic, so a shared topic has one record (the header comment of `shared/learn-sections.ts`).

## What the snapshot prints

1. Learn topics: levels, open levels, Learn questions served, bank questions served, free levels, free part tests, and whether the subject offers the topic.
2. Deliverable questions against `questionCount`, issued coding tasks against `codingChallengeCount`, and whether `shared/coding-index.ts` matches the active catalogue.
3. Plan stages per base track and the bridge topics.
4. Free Learn topics and levels; the free coding share against `FREE_CODING_SHARE`.
5. Coding tasks per track: authored, issued, withheld, evolving stages, free.
6. Each learning path: the line `npm run test:paths` prints, the inventory split by purpose, competencies, bridges, hours.
7. Readiness per path: validator errors and warnings, the switch in this environment, availability once migration 026 is installed. It cannot see the database, so it reports storage as not checked.

The section matrix comes from `LEARN_SECTIONS` and `sectionsForTopic` in `shared/learn-sections.ts`; a topic listed in more than one section is marked shared.

The question counts come from the static bank with the curation gate applied. The script does not read the `/dev` override layer (`question_edits`), so production can differ by the edits stored there.

## Changing a registry

1. Edit the owner listed above, not a copy of it.
2. Run `npm run content:snapshot` before and after; the difference is the change you made.
3. A `MISMATCH`, `OUTSIDE`, `INCOMPLETE` or `STALE` word in the output marks a registry that disagrees with a derived count or a path its validator rejects. The line names the check that will fail (`npm run test:launch` with its contract, or `npm run test:paths`) or, for `STALE`, the command that regenerates the file. Fix the registry or regenerate (`npm run build:coding-index`, `npm run build:curation-registry`), then rerun.

## Validation

| Command | What it proves |
|---|---|
| `npm run content:snapshot` | The registries load together and every count above computes; no number in it is typed |
| `npm run typecheck:scripts` | `scripts/content-snapshot.ts` still matches the registry types after a registry change |
| `npm run test:paths` | The FDE path validates and every reference solution passes; its summary line equals the snapshot's path line |
| `npm run test:launch` | `questionCount`, `codingChallengeCount`, the free coding share, the progression graph and the twelve-handler budget hold |

Report the snapshot output verbatim when you quote a number from it.
